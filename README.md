# Personal Remote Desktop 0.9.25

개인용 Windows 서버·클라이언트 통합 앱과 Android 클라이언트입니다. 서버에 저장한 비밀번호로 수락 없이 접속합니다.

**파일과 텍스트는 클립보드로 양방향 동기화합니다. 기존 파일 보내기·파일 목록·파일 받기 버튼은 삭제했습니다.**

## 실행 파일

- Windows 통합 실행 파일: `artifacts/0.9.25/windows-portable/RemoteDesktop.exe` — 설치 없이 바로 실행하는 단일 EXE. 서버·클라이언트 기능을 모두 포함합니다.
- Android: `artifacts/0.9.25/android/RemoteDesktop-debug.apk` — 접속 중에는 화면을 끝까지 쓰고, 조작은 오른쪽 아래 메뉴의 반투명 하단 바에서 합니다. 다른 앱으로 나갔다가 돌아와도 접속 화면으로 떨어지지 않고 세션을 이어서 붙습니다.

Windows는 별도 설치 과정 없이 실행합니다. 같은 실행 파일에서 **접속 받기**와 원격 클라이언트를 모두 사용할 수 있습니다. 저장된 서버 비밀번호가 있으면 앱을 열 때 접속 대기를 시작합니다. 창을 닫으면 트레이에 남고 접속 대기는 계속됩니다. 트레이의 **종료**를 눌러야 앱이 끝납니다. 접속 대기를 시작하는 동안 같은 버튼을 다시 누르면 포트가 열리기 전에 취소됩니다.

Windows 클라이언트는 서버 지문 입력란을 비워 첫 연결하면 OPAQUE 비밀번호 기반 키 교환으로 서버를 인증하고 TLS 지문을 등록합니다. 지문 등록 뒤에는 해당 지문을 기억하고 기존 고정 TLS 검증을 사용합니다. Android와 기존 서버 비밀번호 설정은 기존 지문 입력 흐름을 사용합니다. OPAQUE 자격 정보는 Windows DPAPI로 보호하고, 비밀번호 변경 때 다시 생성합니다. OPAQUE 등록 정보가 없는 기존 서버 설정은 서버 화면에서 접속을 중지하고 현재 비밀번호를 한 번 다시 입력해 **보안 등록**을 완료할 수 있습니다. 기존 PBKDF2 비밀번호는 확인만 하며 바뀌지 않습니다.

## Windows 실행 파일 용량

기본 Windows EXE가 약 83MB인 이유는 앱 코드가 아니라 WPF, WinForms 화면·입력 API, ASP.NET Core Kestrel, .NET 런타임과 Windows 네이티브 그래픽 라이브러리를 함께 포함하기 때문입니다. 앱 코드 DLL 자체는 약 0.15MB이며, 기존 191MB 빌드는 자체 포함 런타임을 압축하지 않은 단일 파일이었습니다.

기본 산출물은 압축된 자체 포함 EXE입니다. .NET 10 Windows Desktop Runtime과 ASP.NET Core Runtime이 있는 PC에서는 다음 명령으로 약 0.3MB의 프레임워크 종속 EXE를 만들 수 있습니다.

```powershell
./build.ps1 -FrameworkDependent
```

프레임워크 종속 산출물은 `artifacts/0.9.25/windows-framework-dependent/RemoteDesktop.exe`에 생성되며 대상 PC에 런타임 설치가 필요합니다. 기본 자체 포함 압축본은 설치 없이 실행되지만 첫 실행 시 내부 런타임을 임시 폴더에 풀기 때문에 시작이 조금 느리고 실행 중 디스크 공간을 추가로 사용합니다.

## 접속

서버 탭의 **끊김 줄이기**는 기본으로 켜져 있습니다. 접속 대기 중 호스트 프로세스 우선순위를 한 단계 높이고 캡처 스레드를 더 높은 우선순위로 실행합니다. 실시간 우선순위는 사용하지 않습니다. 화면 변화가 없으면 마지막 JPEG을 재사용하고, 변화가 있으면 캡처와 인코딩을 미리 준비합니다. 처리 시간이 목표 프레임 주기를 넘기면 JPEG 품질을 낮춰 밀린 프레임을 줄입니다. Windows 클라이언트의 포인터는 원격 화면 프레임에 포함되어 화면 크기가 바뀌어도 클릭 위치와 같은 좌표계를 사용합니다. 이 최적화는 직접 실행하는 서버에도 적용됩니다.

서버 탭에서 비밀번호를 한 번 설정하면 접속 대기를 시작합니다. 이후 앱을 실행할 때 저장된 포트·비밀번호·서버 인증서로 자동 대기합니다. **서버 중지**는 현재 앱 프로세스에서 실행 중인 호스트를 중지합니다. 비밀번호를 바꾸려면 서버 중지 → 비밀번호 변경 → 저장을 사용합니다.

Windows 서버 TLS 키는 Schannel이 사용할 수 있도록 현재 사용자 프로필의 임시 키 저장소에 불러옵니다. 앱을 닫으면 임시 키가 정리되며 관리자 권한이나 Windows 서비스 등록은 필요하지 않습니다.

포트 사용 중, 잘못된 포트, 네트워크 권한 문제로 접속 대기가 실패하면 상단 상태 표시줄에 원인을 표시합니다. 이전 버전에서 Windows 서비스가 등록된 PC라면 새 앱 실행 전에 관리자 PowerShell에서 기존 서비스를 한 번 제거해야 합니다. `sc.exe stop PersonalRemoteDesktop` 후 `sc.exe delete PersonalRemoteDesktop`을 실행하세요. 이전 버전에서 로그인 자동 실행을 켰다면 현재 사용자 PowerShell에서 `Remove-ItemProperty -Path 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Run' -Name 'Personal Remote Desktop' -ErrorAction SilentlyContinue`도 실행하세요. 서버 설정은 `%LOCALAPPDATA%\PersonalRemoteDesktop`에 그대로 두면 됩니다.

클라이언트에 서버 주소와 포트를 각각 입력하고 비밀번호를 입력합니다. Windows에서는 서버 SHA-256 지문을 비우면 비밀번호로 서버 키를 처음 확인하고 지문을 저장합니다. 지문을 직접 입력한 경우에는 해당 지문을 고정해 검증합니다. Android는 지문 입력이 필요합니다. 기본 포트는 45831입니다. 비밀번호 입력란에서 Enter를 누르면 접속 버튼과 같은 동작을 합니다. 마지막 주소·포트·지문·선택 모니터를 기억하며 클라이언트 비밀번호는 디스크에 저장하지 않습니다. Android는 다른 앱으로 나갔다가 다시 붙기 위해 그 실행 동안만 비밀번호를 메모리에 두고, 접속을 종료하거나 프로세스가 끝나면 지웁니다.

현재 연결 범위는 LAN/VPN입니다. 접속 대기를 시작하면 이 프로그램의 수신 포트를 개인 및 도메인 네트워크 방화벽에서 허용하고, 모든 사용자 설치를 제거하면 그 규칙을 지웁니다. 로그인한 서버 데스크톱에서 앱이 실행 중이어야 합니다.

실행 파일만으로 바로 쓸 수 있습니다. 이 PC 탭에서 **이 사용자만 설치**하면 시작 메뉴와, 선택하면 로그인 후 자동 실행이 추가됩니다. 설치한 뒤에는 그 항목을 같은 자리에서 켜고 끌 수 있습니다. 모든 사용자에게 설치하면 이전 사용자 설치의 시작 메뉴와 자동 실행은 지웁니다. **모든 사용자에게 설치**는 관리자 권한으로 Program Files에 두고 Windows 서비스를 등록합니다. 그 서비스는 로그인한 뒤 접속 대기를 이어 가고, UAC 보안 화면을 상대 PC에 보내며 클릭과 키를 그 화면으로 전달합니다. 설치하지 않았거나 이 사용자만 설치한 경우에는 로그인한 일반 데스크톱만 제어합니다. Ctrl+Alt+Del은 모든 사용자 설치의 서비스만 원격으로 보낼 수 있습니다. 그 외에는 보내지 않고 안내만 표시합니다. [SendSAS 문서](https://learn.microsoft.com/en-us/windows/win32/api/sas/nf-sas-sendsas)

## Windows 파일 복사·붙여넣기

### 내 PC → 서버

1. 내 PC의 탐색기에서 파일을 선택하고 **Ctrl+C**합니다.
2. 원격 화면에서 대상 탐색기 폴더를 엽니다.
3. **Ctrl+V**하면 전송 완료를 기다린 뒤 원격 탐색기에 붙여넣습니다.

연결 중 새로 복사한 파일은 자동으로 서버 클립보드에 준비됩니다. ‘클립보드 파일 준비 완료’가 표시되면 서버 PC에서 직접 Ctrl+V해도 됩니다. 파일의 최종 저장 위치는 탐색기에서 선택한 폴더입니다.

### 서버 → 내 PC

1. 원격 탐색기에서 파일을 선택하고 **Ctrl+C**합니다.
2. ‘클립보드 파일 수신 완료’를 기다립니다.
3. 내 PC 탐색기의 대상 폴더에서 **Ctrl+V**합니다.

양방향 전송이므로 별도의 서버 파일 목록 화면이나 보내기 버튼이 필요하지 않습니다. 파일은 Windows 파일 드롭 클립보드(CF_HDROP)에 올라갑니다. 대상 탐색기가 이름 충돌 처리를 담당합니다.

연결 직전의 오래된 클립보드를 자동 전송하지는 않습니다. 연결 후 새로 복사하세요. Windows 클라이언트에서 원격 Ctrl+V를 누르는 경우에는 연결 전에 복사한 로컬 파일도 전송할 수 있습니다.

## 텍스트 클립보드

Windows 서버·클라이언트는 연결된 동안 일반 텍스트를 복사하면 상대 PC의 텍스트 클립보드에도 반영합니다. 한글, 줄바꿈, 이모지 같은 Unicode 텍스트를 지원합니다. Windows와 Android에서 서식 있는 글을 복사하면 그 HTML도 함께 붙습니다. HTML을 받지 않는 앱에서는 일반 텍스트로 붙여넣습니다. 복사한 뒤 원격 화면에서 Ctrl+V를 누르면 즉시 동기화한 텍스트를 붙여넣습니다.

Android도 기본 클립보드의 일반 텍스트를 자동 동기화합니다. 서버에서 온 텍스트는 Android 시스템 클립보드에 들어가므로 지원 앱에서 일반 붙여넣기를 사용하면 됩니다. 파일 URI 클립보드와 텍스트 클립보드는 한 번에 하나만 활성화됩니다. 클립보드를 비우면 상대쪽 텍스트와 파일 클립보드도 지웁니다. Android도 서식 있는 글을 HTML로 주고받습니다. 파일이나 글이 없는 그림은 Windows와 Android가 PNG로 주고받으며, JPEG나 WebP로 복사해도 PNG로 바꿔 보냅니다. 16MB를 넘기면 보내지 않습니다.

텍스트는 최대 100만 자입니다. 전송 중 다른 PC에서 새 텍스트를 복사하면 새 내용이 우선하며, 같은 내용이 양쪽에서 반복 전송되지 않습니다.

## Android 파일 클립보드

Android의 파일 관리 앱마다 클립보드 지원 방식이 달라 Windows 탐색기와 동일한 전역 파일 붙여넣기를 가정하지 않습니다. 앱의 **클립보드** 메뉴를 사용합니다.

- **Android → 서버:** 파일 URI를 클립보드에 복사하거나 다른 앱에서 파일 선택 → 공유 → Remote Desktop을 선택합니다. 서버에 접속하고 원격 대상 폴더를 연 뒤, 클립보드 메뉴의 **복사한 파일 → 원격에 붙여넣기**를 선택합니다.
- **서버 → Android:** 원격 탐색기에서 파일을 복사한 뒤 **원격에서 복사한 파일 가져오기**를 선택합니다. 검증된 파일이 Android 클립보드의 `content://` URI로 등록됩니다.
- 파일 URI 붙여넣기를 지원하는 앱에서는 그대로 사용합니다. 그렇지 않으면 **복사한 파일 → 이 기기 폴더에 붙여넣기**에서 저장 폴더를 선택합니다.
- Android 클립보드 메뉴의 **전송 취소**는 원격 전송과, 이 기기 폴더로 붙여넣는 중에 모두 동작합니다. 폴더 붙여넣기를 취소하면 이번 붙여넣기로 만든 파일과 폴더만 지웁니다.

다른 앱에는 읽기 전용 URI 접근 권한만 제공하며 앱 내부의 임의 파일을 공개하지 않습니다. 텍스트를 파일 경로로 해석해서 읽는 기능은 없습니다.

## Android 터치 방식

연결 후 오른쪽 아래 **메뉴**에서 **터치: 직접**을 눌러 다음 방식 중 하나를 선택합니다. 선택한 방식은 다음 실행에도 기억합니다.

- **직접 터치:** 누른 위치에서 바로 좌클릭을 시작합니다. 손가락을 옮기면 좌클릭 드래그입니다.
- **터치패드:** 화면에서 드래그하면 현재 원격 커서를 상대 이동합니다. 이동 없이 탭하면 현재 커서를 좌클릭합니다.
- **터치패드 + 길게 누르기:** 터치패드와 같고, 이동 없이 길게 누르면 현재 커서를 우클릭합니다. 길게 누르기를 시작한 뒤 손가락을 옮기면 우클릭을 보내지 않습니다.
- 입력이 켜져 있으면 원격 커서를 영상 안에 굽지 않고 화면 위에 따로 그립니다. 손가락이나 터치패드 커서를 바로 따라가고, 입력 제어를 끄면 다시 영상 안의 커서를 봅니다.

두 손가락 이상을 쓰거나 앱 포커스를 잃으면 진행 중인 터치 조작을 해제합니다. 기존 하단 우클릭 버튼도 계속 사용할 수 있습니다.

## 전송 정책

- 일반 파일 1~100개, 파일당 최대 1GiB, 한 번에 최대 4GiB입니다.
- 폴더 안의 일반 파일은 하위 폴더와 함께 복사됩니다. 빈 폴더도 그 자리에 남습니다. 파일이나 글이 없는 그림은 Windows와 Android 클립보드의 그림으로 복사됩니다. Windows와 Android는 서식 있는 글을 HTML과 함께 복사합니다. HTML을 받지 않는 앱에서는 일반 텍스트로 붙여넣습니다. 심볼릭 링크와 가상 첨부파일 스트림은 지원하지 않으며 RTF는 보내지 않습니다.
- 파일은 청크 단위로 전송하고 크기와 SHA-256을 검증합니다. 배치의 모든 파일이 검증되기 전에는 대상 클립보드를 바꾸지 않습니다.
- 서버의 업로드 완료 시 클립보드가 다른 내용으로 변경됐으면 충돌로 거부합니다. 클라이언트도 수신 중 사용자가 새로 복사한 클립보드를 덮어쓰지 않습니다.
- 출처 표시로 같은 파일이 양쪽을 반복해서 오가는 것을 막습니다.
- 같은 이름의 여러 파일은 개별 임시 디렉터리에 보관해 전송 중 서로 덮어쓰지 않습니다.
- 원본은 삭제하지 않습니다. 잘라내기로 선택했더라도 원격 전송은 **복사**로 처리합니다.
- 실패·취소·연결 종료 시 미완료 업로드는 정리합니다. 완료된 캐시는 연결 종료 뒤에도 붙여넣을 수 있게 유지합니다.
- Windows 완료 캐시: `%LOCALAPPDATA%\PersonalRemoteDesktop\ClipboardCache`. Android 완료 캐시: 앱 전용 `files/clipboard`. 지금 붙여넣을 파일은 남기고, 더 이상 가리키지 않는 이전 배치는 지웁니다. 끊긴 파일 전송은 이미 받은 바이트 다음부터 이어받습니다. 진행이 없는 업로드는 2분 뒤 지워집니다.

파일은 복사 시점부터 전송되므로 큰 파일은 준비 완료까지 시간이 걸립니다. 전체화면에서도 전송 상태를 표시합니다. 전송 중에는 화면 아래 **전송 취소**가 나타나고, 취소하면 아직 끝나지 않은 파일은 상대 클립보드에 들어가지 않습니다.

## 화면과 입력

- 개별 모니터 또는 전체 모니터를 선택할 수 있습니다. 음수 좌표에 배치된 모니터도 입력 좌표를 보정합니다.
- Windows는 F11 또는 전체화면 버튼으로 진입·복귀합니다.
- Android는 접속하면 상태 표시줄과 탐색 표시줄을 숨깁니다. 화면 가장자리에서 스와이프하면 잠시 나타납니다. 모니터·키보드·클립보드·화질은 오른쪽 아래 **메뉴**에 있습니다.
- Windows 화면 클릭 후 키 입력을 서버로 직접 전달합니다. 한/영 키 또는 한/영 버튼을 사용할 수 있으며 서버에 한국어 IME가 설치되어 있어야 합니다.
- 원격 화면에 포커스가 있으면 Alt+Tab, Alt+F4, Win 조합, Ctrl+Esc, Ctrl+Shift+Esc, Print Screen을 원격 PC에 우선 전달합니다. Ctrl+Alt+Del은 Windows가 가로채므로 키보드로 전달하지 않습니다. 조작 메뉴의 Ctrl+Alt+Del로 보내고, 모든 사용자 설치가 아니면 안내만 표시됩니다.
- Android는 기본 키보드로 한글을 조합하고 확정된 문자열을 전송 버튼 없이 전달합니다. 조합 중 문자열은 화면 위 상태 표시에 남아 있고, 확정되면 곧 사라집니다.
- Windows 원격 세션은 기본적으로 로그인한 사용자의 일반 데스크톱을 대상으로 합니다. 모든 사용자 설치의 Windows 서비스가 켜져 있으면 UAC 보안 화면도 상대 PC에 보이고, 그 화면으로 조작이 전달됩니다. Android도 보안 화면이 보이거나, 설치가 없어 그 화면이 보이지 않으면 화면 아래에 안내를 남겨 둡니다. 조작 바가 열려 있는 동안에는 그 안내를 숨깁니다. Ctrl+Alt+Del은 그 서비스가 켜져 있을 때 조작 메뉴에서 보낼 수 있습니다. [Microsoft SendSAS 문서](https://learn.microsoft.com/en-us/windows/win32/api/sas/nf-sas-sendsas)

## 세션 툴바

Windows 세션에는 다음 조작을 한 줄로 모았습니다.

- **입력 제어:** 끄면 원격 화면은 계속 보이지만 마우스·키보드·텍스트 전송을 전달하지 않습니다. 끌 때 누른 키와 마우스 버튼을 해제합니다.
- **Ctrl+Alt+Del:** 조작 메뉴에서 원격 PC의 보안 화면을 엽니다. 모든 사용자 설치의 서비스가 켜져 있을 때만 전달되고, 아니면 안내만 표시됩니다.
- **클립보드 자동:** 양방향 자동 동기화를 켜거나 끕니다. 자동 동기화가 꺼져도 **지금 보내기**, **지금 받기**로 한 번만 동기화할 수 있습니다.
- **화면 품질:** 저대역폭(30), 균형(55), 고화질(75)을 선택합니다. H.264에서는 비트레이트에, JPEG에서는 압축 품질에 반영됩니다. 선택값은 다음 연결에도 유지됩니다. 그림 전송이 목표 간격보다 늦으면 Windows와 Android가 그 선택을 잠시 낮추고, 다시 여유가 생기면 원래 화질로 돌아갑니다.
- **최대 FPS:** 5·10·15·30 FPS 중 선택합니다. 프레임 요청과 JPEG 처리 시간이 목표 주기보다 길면 실제 FPS는 그보다 낮을 수 있습니다.
- **세션 정보:** 대상 주소, 선택 모니터, 수신 해상도, 요청·전송·서버 화질, 캡처·압축 시간, 프레임 크기, 화면 재사용, 왕복 지연, 입력·클립보드 상태를 확인합니다.
- **상태 표시:** 수신 FPS와 최근 왕복 지연을 표시합니다. 전체화면에서도 세션 툴바는 남아 있습니다.

Windows와 Android 클라이언트는 화면을 H.264로 요청합니다. 호스트가 H.264를 만들지 못하거나 Android 디코더가 반복해서 실패하면 JPEG로 표시합니다. `codec`을 생략하는 이전 클라이언트는 JPEG를 그대로 받습니다.

Android도 입력 제어 토글, Ctrl+Alt+Del 버튼, 화면 품질·최대 FPS 선택, 세션 정보와 FPS·최근 프레임 시간 표시를 제공합니다.

Android 화면에서 두 손가락으로 핀치 확대·축소할 수 있습니다. 확대된 상태에서 한 손가락을 드래그하면 보고 있는 영역을 이동하고, 서버에는 현재 viewport만 요청해 전체 모니터를 매번 보내지 않습니다. `저대역폭`을 선택하면 품질 25·5 FPS로 전환됩니다. H.264로 보는 동안 이 값은 비트레이트에 반영되고, JPEG로 돌아온 경우에는 JPEG 품질로 적용됩니다. 실제 FPS와 전송량은 서버 캡처·인코딩·네트워크 상태에 따라 더 낮아질 수 있습니다.

연결이 성공하면 Windows와 Android 모두 주소·비밀번호·서버 지문 입력 영역을 자동으로 숨깁니다. Windows 상단에는 입력 제어, 모니터 선택, `조작 ▾`, FPS·지연만 남습니다. 화질·FPS·화면 확대·클립보드·한/영·Ctrl+Alt+Del·전체화면·세션 정보·종료는 `조작 ▾` 메뉴에 모았습니다. 화면 확대는 100%·150%·200%·400%입니다. 확대한 뒤에는 휠 버튼으로 끌어 보이는 부분만 서버에 요청하고, 클릭은 그 위치에 맞춥니다. Android는 원격 화면을 시스템 바 뒤까지 가득 채웁니다. 오른쪽 아래 **메뉴**를 누르면 반투명 하단 조작 바가 열리고, 화면을 건드리면 바로 닫히며 그대로 두면 잠시 후 숨습니다. 뒤로 가면 그 바가 열려 있을 때는 바를 닫고, 원격 화면만 보고 있으면 연결을 끊을지 확인합니다. 그 바에 Ctrl+Alt+Del이 있습니다. 접속을 종료하면 접속 정보 영역이 다시 표시됩니다. Android에서 다른 앱으로 이동하면 화면 전송만 멈추고 약 5초마다 세션을 갱신합니다. 돌아왔을 때 세션이 살아 있으면 화면을 바로 재개하고, 서버가 세션을 버린 경우에는 메모리의 비밀번호로 다시 로그인한 뒤 마지막 화면을 유지합니다.

## 빌드와 검사

```powershell
 dotnet build src/RemoteDesktop/RemoteDesktop.csproj
 dotnet run --project src/RemoteDesktop
 ./build.ps1
 ./build.ps1 -Android
 dotnet run --project tests/IntegrationChecks -- --capture
```

Windows는 .NET SDK 10, Android는 SDK Platform 35 / Build Tools 35.0.0 / JDK가 필요합니다. Android 빌드는 SDK 도구를 직접 사용하며 경로는 `android/build.ps1 -Sdk ... -Jdk ...`로 지정할 수 있습니다.

통합 검사는 실제 HTTPS와 파일 IO를 사용합니다. OS 클립보드는 테스트 대역으로 대체하므로 사용자의 클립보드를 읽거나 덮어쓰지 않습니다. 양방향 파일·텍스트 전송, 한글·줄바꿈·긴 텍스트, 해시 오류, 미완료 배치, 취소, 출처 중복 방지, 새 클립보드 보존, 한글·중복 파일명, 세션 만료, 모니터 캡처, 끊김 줄이기 설정을 검증합니다.

Windows 빌드와 Android APK 생성·서명 검증을 수행합니다. 실제 탐색기의 붙여넣기와 Android 앱 간 URI 공유·붙여넣기, 실제 IME 입력, 1GiB·장시간 전송은 별도 실기 검증이 필요합니다. 현재 환경에는 연결된 Android 기기가 없습니다. 빌드 도구의 NuGet 취약성 정보 조회 네트워크 경고와 JDK 호환 경고가 발생할 수 있습니다.

## 코드

- `MainWindow.xaml(.cs)`: Windows UI, 원격 입력과 붙여넣기 연결.
- `Desktop.cs` / `DxgiDisplayCapture.cs` / `HostPerformance.cs`: 화면 캡처 재사용, DXGI 캡처, 적응형 화질과 우선순위 기반 끊김 완화.
- `FileClipboard.cs`: STA 클립보드 접근, 파일 드롭 형식, 이름·크기 제한.
- `ClipboardExchange.cs`: 서버 파일 스냅샷, 배치 업로드, 검증 후 클립보드 교체.
- `ClipboardSync.cs`: Windows 양방향 동기화, 출처·충돌 처리.
- `RemoteHost.cs` / `RemoteClient.cs`: HTTPS 인증·세션·전송.
- `SecureAttention.cs`: 모든 사용자 설치의 서비스만 Ctrl+Alt+Del을 보냅니다.
- `android/.../ClipboardFiles.java`: Android 클립보드·공유·폴더 붙여넣기.
- `android/.../ClipboardProvider.java`: 읽기 전용 파일 URI.

공유 폴더 `/v1/files` API, 호출되지 않던 `/v1/health`, 숨겨 둔 폴더 설정은 제거했습니다. 파일은 클립보드 경로로만 이동합니다. 구조 개선 순서는 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)를 참고하세요.


창을 닫으면 트레이로 들어가고 접속 대기와 보고 있던 화면은 유지됩니다. 트레이에서 종료하면 호스트와 연결을 정리하고 앱이 끝납니다. 앱을 다시 실행하면 숨긴 창을 앞으로 가져옵니다.
